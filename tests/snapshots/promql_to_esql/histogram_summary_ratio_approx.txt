source: sum(increase(prometheus_tsdb_compaction_duration_sum{instance="$instance"}[30m]) / increase(prometheus_tsdb_compaction_duration_count{instance="$instance"}[30m])) by (instance)
feasibility: feasible
warning: Approximated PromQL arithmetic using same-bucket ES|QL math
warning: Dropped variable-driven label filters during migration
warning: Dropped the source rate()/irate()/increase() lookback window [30m]: ES|QL computes RATE/IRATE/INCREASE over the query's time bucket, so this panel now reports a rate over the fixed 5-minute time bucket instead of that window. Panels that differ only by such a window produce the same values here. Native PROMQL preserves the window and is the default when the target supports the ES|QL PROMQL command.
warning: Approximated sum(increase|rate(m_sum)/increase|rate(m_count)) as a ratio of aggregates (sum(m_sum)/sum(m_count)); per-series means are not weighted the same as Prometheus
---
TS metrics-*
| WHERE @timestamp >= ?_tstart AND @timestamp <= ?_tend
| WHERE prometheus_tsdb_compaction_duration_sum IS NOT NULL OR prometheus_tsdb_compaction_duration_count IS NOT NULL
| STATS prometheus_tsdb_compaction_duration_sum_instance_increase_sum = SUM(INCREASE(prometheus_tsdb_compaction_duration_sum)), prometheus_tsdb_compaction_duration_count_instance_increase_sum = SUM(INCREASE(prometheus_tsdb_compaction_duration_count)) BY time_bucket = TBUCKET(5 minute), service.instance.id
| EVAL computed_value = (prometheus_tsdb_compaction_duration_sum_instance_increase_sum / prometheus_tsdb_compaction_duration_count_instance_increase_sum)
| KEEP time_bucket, service.instance.id, computed_value
| SORT time_bucket ASC
